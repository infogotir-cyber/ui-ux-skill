AI CRM for a Roofing Company

Open live demo

Problem

Roofing sales teams generate leads from many channels — storm canvassing, ads, referrals, insurance adjusters — but without a structured CRM, leads live in someone's phone or a spreadsheet. Follow-ups slip, estimates get lost, and nobody can see the real state of the pipeline.

Solution

A GoHighLevel-style CRM structured around the roofing sales cycle: a kanban pipeline with stages from New Lead to Won/Lost, a searchable contacts list, per-customer timelines, task management, a quotes module, and a follow-up calendar — all tied together with a KPI overview so the owner can see the business at a glance.

Architecture

Intake
Web forms and ad platforms feed leads into the CRM via webhook, with AI scoring applied on arrival.
Pipeline
Deals move through 7 stages; kanban and list views share the same underlying data model.
Engagement
Tasks, quotes and the follow-up calendar keep reps and the office in sync on next actions.
Reporting
KPI cards and charts roll pipeline value, win rate and crew utilization up for leadership.

Screenshot — live preview

app.automation-os.dev/dashboard.html

Technologies

GoHighLevel-style CRMn8nOpenAI lead scoringApexChartsFullCalendar

Lessons Learned

  • A CRM only gets used if it matches the team's actual vocabulary — stage names and fields were modeled on how roofing reps already talk about a job.
  • Kanban and list views need to share one data model, or reps start trusting one view over the other and data drifts.
  • KPI cards are only useful if they answer a question someone already asks in a Monday meeting.

Lead capture and CRM updates run through automation instead of manual re-typing.

Lead Qualification Automation

Open live demo

Problem

Not every inbound lead deserves the same urgency — a storm-damage lead with full insurance coverage should be called in minutes, while a vague inquiry can wait for the nurture sequence. Manually triaging every lead doesn't scale, and treating them all the same wastes the sales team's time.

Solution

An n8n workflow that receives every lead through a webhook, sends it to OpenAI for priority scoring based on urgency, storm timing and insurance language, then branches: high-priority leads are logged, pushed into the CRM and routed straight to a rep, while the whole team gets visibility through Google Sheets, email and Slack.

Architecture

Trigger
A website or Facebook Lead Ad form submission fires a webhook with the raw lead payload.
AI scoring
OpenAI returns a structured priority score and recommended action using a purpose-built prompt.
Branch
A condition node splits high-priority leads from standard ones.
Fan-out
Google Sheets logging, a GoHighLevel upsert, an automatic email, and a Slack alert all fire from the same event.

Screenshot — live preview

app.automation-os.dev/workflow-gallery.html

Technologies

n8nOpenAIWebhooksGoogle Sheets APIGoHighLevel APISlack API

Lessons Learned

  • AI scoring is only trustworthy if the prompt is specific about what "urgent" means in this business — vague prompts produce vague scores.
  • Fan-out steps (Sheets, CRM, email, Slack) should be independent, so one failing service doesn't block the others.
  • A visual canvas makes it dramatically easier to explain the automation to a non-technical business owner than a code review would.

Business Impact

Documentation System · Concept Project

Business SOP Manager

Open live demo

Problem

Process knowledge tends to live in one person's head, a scattered set of Google Docs, or nowhere at all. When that person is out — or leaves — the process breaks, and new hires take far longer to ramp up than they should.

Solution

A searchable SOP library organized by category, with each procedure structured the same way: an AI-generated summary for a quick read, numbered steps, a completion checklist, and a version history so changes are traceable over time.

Architecture

Structure
Every SOP follows the same template: summary, steps, checklist, version history — easy to scan, easy to maintain.
Search & filter
Full-text search plus category filters help someone find the right procedure in seconds, not minutes.
AI summary
A short OpenAI-generated summary sits above the full procedure so people get the gist before committing to reading it.
Versioning
Each update is logged with author and date, so the team can see what changed and why.

Screenshot — live preview

app.automation-os.dev/sop-center.html

Technologies

Notion-style documentationOpenAI summarizationFull-text search

Lessons Learned

  • A consistent template matters more than exhaustive detail — people trust and use SOPs that are predictable to scan.
  • An AI summary at the top dramatically increases the odds someone actually reads the SOP instead of skipping it.
  • Version history isn't just an audit trail — it builds trust that the document in front of you is current.

Business Impact

Automation Monitoring Dashboard

Open live demo

Problem

Once a business has a dozen automations running quietly in the background, "is it actually working?" becomes a real question. Without visibility, failures get discovered by an angry customer or a missed deadline instead of a dashboard.

Solution

A monitoring dashboard that surfaces execution counts, success rate, error counts and running workflows at a glance, backed by a searchable execution log with per-run status, duration and error detail for every workflow in the business.

Architecture

Execution log
Every workflow run — success, error or in-progress — is recorded with timing and trigger type.
Aggregation
KPI cards and charts summarize executions, success rate and average run time across the whole automation portfolio.
Per-workflow breakdown
A workflow table shows run counts and success rate per automation, surfacing which ones need attention.
Filtering
The log can be filtered by status, so a break can be triaged in seconds during an incident.

Screenshot — live preview

app.automation-os.dev/automation-monitor.html

Technologies

n8n execution dataApexChartsReal-time-style log filtering

Lessons Learned

  • Aggregate KPIs answer "is everything OK?" — the detailed log answers "what exactly broke?" Both are needed, at different moments.
  • Filtering by status is the single most-used feature in any monitoring view — it needs to be one click, not a search query.
  • Success rate per workflow, not just overall, is what actually tells you where to focus maintenance effort.
